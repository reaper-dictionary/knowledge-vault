

> [!summary] Главная идея  
> Docker запускает контейнер. Kubernetes поддерживает **желаемое состояние** системы: нужное количество экземпляров, сеть, конфигурацию, обновления и восстановление после сбоев.

## Десять терминов на первый этап

|Термин|Простое значение|Аналогия|
|---|---|---|
|Cluster|Вся система Kubernetes|Город|
|Node|Машина кластера|Дом|
|Pod|Минимальная среда запуска контейнера|Квартира|
|Deployment|Управляет одинаковыми stateless Pod|Управляющая компания|
|Service|Стабильный адрес группы Pod|Общий номер приёмной|
|Ingress|Правила внешнего HTTP/HTTPS|Таблица маршрутов на входе|
|Namespace|Логическое разделение ресурсов|Район|
|ConfigMap|Обычная конфигурация|Настройки|
|Secret|Чувствительная конфигурация|Закрытые данные|
|Volume|Подключённое хранилище|Диск / кладовая|

Сначала уверенно запомни только их. Остальные термины будут привязаны к практике.

## Устройство кластера

```
Cluster
├── Control Plane — принимает решения и хранит состояние кластера
└── Worker Node — запускает workload
    └── Pod
        └── Container
```

**Control Plane** следит, чтобы фактическое состояние пришло к описанному в manifests. **Worker Node** предоставляет CPU, RAM и container runtime для Pod.

`kubectl` — CLI-клиент, который отправляет запросы Kubernetes API.

## Manifest и желаемое состояние

Manifest — YAML-описание объекта:

```
apiVersion: apps/v1
kind: Deployment
metadata:
  name: marketplace-api
spec:
  replicas: 3
```

Смысл:

```
«В кластере должны работать три экземпляра Marketplace API»
```

Если один Pod исчезнет, контроллер создаст замену.

## Pod

Pod — минимальная единица запуска Kubernetes. В нём обычно один основной контейнер, но контейнеров может быть несколько, если они должны разделять сеть и volumes.

Pod временный:

- может быть удалён и создан заново;
    
- получает новый IP;
    
- может переместиться на другую Node;
    
- не является местом для единственной копии важных данных.
    

FastAPI внутри Pod обычно слушает:

```
0.0.0.0:8000
```

Если слушать только `127.0.0.1:8000`, Service обычно не сможет подключиться к приложению по Pod IP.

## Deployment, ReplicaSet и replicas

```
Deployment
└── ReplicaSet
    ├── Pod API #1
    ├── Pod API #2
    └── Pod API #3
```

**Deployment**:

- поддерживает количество replicas;
    
- заменяет упавшие Pod;
    
- выполняет rolling update;
    
- позволяет откатить версию;
    
- масштабирует stateless-приложение.
    

ReplicaSet обычно не создают вручную — его создаёт Deployment.

## Labels и selectors

Label — метка объекта:

```
labels:
  app: marketplace-api
```

Selector — условие поиска по labels:

```
selector:
  app: marketplace-api
```

Так Deployment и Service находят нужные Pod. Ошибка в label/selector часто приводит к тому, что Service существует, но у него нет endpoints.

## Service

IP Pod временный. Service предоставляет стабильное DNS-имя и направляет трафик на подходящие Pod.

```
marketplace-api Service
        ↓ selector app=marketplace-api
Pod #1 / Pod #2 / Pod #3
```

Основные типы:

|   |   |
|---|---|
|Тип|Назначение|
|`ClusterIP`|Доступ только внутри кластера; тип по умолчанию|
|`NodePort`|Открывает порт на каждой Node|
|`LoadBalancer`|Запрашивает внешний балансировщик у инфраструктуры|

Для PostgreSQL, Redis и Kafka обычно нужен внутренний `ClusterIP`, а не внешний HTTP-вход.

## `port` и `targetPort`

```
ports:
  - port: 80
    targetPort: 8000
```

```
Service:80 → Pod:8000 → FastAPI
```

## Ingress и Ingress Controller

Ingress хранит HTTP/HTTPS-правила:

```
marketplace.example/api → API Service
marketplace.example/    → Frontend Service
```

Сам объект Ingress не проксирует трафик. Нужен **Ingress Controller** — реальная программа, выполняющая правила.

```
Интернет → Ingress Controller → Service → Pod
```

Ingress остаётся стабильным и широко используется, но его API заморожен. Для новых возможностей Kubernetes развивает Gateway API.

## ConfigMap и Secret

|   |   |
|---|---|
|Объект|Пример|
|ConfigMap|`LOG_LEVEL`, адрес Kafka, feature flag|
|Secret|`DB_PASSWORD`, signing key, registry credentials|

ConfigMap отделяет обычную конфигурацию от image.

> [!warning]  
> Base64 в Secret — кодирование, а не шифрование. Нужны ограниченные права, encryption at rest и аккуратная передача secret в приложение.

## Volume, PV и PVC

```
PV  → доступный persistent storage
PVC → запрос приложения на storage
```

|   |   |
|---|---|
|Термин|Значение|
|Volume|Хранилище, подключённое к Pod|
|PersistentVolume (PV)|Выделенный persistent storage в кластере|
|PersistentVolumeClaim (PVC)|Запрос workload на storage|
|StorageClass|Правила динамического создания storage|

Pod может исчезнуть, а данные на корректно настроенном PV сохраняются.

## Проверки здоровья

|   |   |   |
|---|---|---|
|Probe|Вопрос|Реакция|
|Readiness|Готово ли приложение принимать трафик?|Pod убирается из endpoints Service|
|Liveness|Не зависло ли приложение?|Контейнер перезапускается|
|Startup|Успело ли медленное приложение запуститься?|Защищает старт от преждевременной liveness-проверки|

Readiness и liveness отвечают на разные вопросы; один endpoint бездумно использовать для обеих проверок не стоит.

## Requests и limits

```
requests → сколько ресурсов нужно зарезервировать для планирования
limits   → установленный верхний предел
```

```
resources:
  requests:
    cpu: 100m
    memory: 128Mi
  limits:
    memory: 256Mi
```

Scheduler использует requests, чтобы выбрать Node. Поведение CPU и memory limits различается: CPU throttled, а превышение memory может привести к OOM kill.

## Другие workload

|   |   |
|---|---|
|Объект|Когда нужен|
|StatefulSet|Стабильные имена и storage для stateful workload|
|Job|Выполнить задачу до завершения|
|CronJob|Запускать Job по расписанию|
|DaemonSet|Запустить Pod на каждой подходящей Node|

PostgreSQL можно изучать через StatefulSet, но для первого деплоя учебного API лучше начать с одного stateless Deployment.

## Минимальные команды

```
kubectl apply -f deployment.yaml
kubectl get pods
kubectl get deployments
kubectl get services
kubectl describe pod <pod-name>
kubectl logs <pod-name>
kubectl rollout status deployment/marketplace-api
```

```
get      → краткое состояние
describe → события и подробности объекта
logs     → stdout/stderr контейнера
```
