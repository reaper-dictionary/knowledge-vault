# Gateway, WebSocket и наблюдаемость realtime-системы

> [!info] Как пользоваться заметкой  
> Запомни границу Gateway: transport, authentication edge, routing, aggregation и realtime connections. Бизнес-решения остаются в Identity, Wallet и Casino.

---

# 1. Краткие определения — выучить

## API Gateway

> **API Gateway** — внешняя точка входа, которая завершает клиентское соединение, проверяет базовую authentication, маршрутизирует запрос, применяет rate limit и преобразует transport errors.

## BFF

> **Backend for Frontend (BFF)** — gateway-слой, адаптированный под потребности конкретного клиента: web, mobile или admin. Он агрегирует данные, но не становится владельцем бизнес-правил.

## WebSocket

> **WebSocket** — постоянное двунаправленное соединение поверх TCP после HTTP Upgrade, позволяющее серверу и клиенту отправлять сообщения независимо.

## Connection registry

> **Connection registry** — временная карта `user/session → connection`, используемая Gateway для отправки сообщений и очистки соединения после disconnect.

## Presence

> **Presence** — эфемерное состояние online/room membership для текущего соединения. Presence не заменяет постоянную запись участника комнаты в Casino.

## Snapshot

> **Snapshot** — полное актуальное состояние ресурса на определённой revision, которое клиент получает при подключении или восстановлении после пропущенных событий.

## Revision

> **Revision** — монотонная версия состояния комнаты. Клиент применяет только события новее своей revision и обнаруживает пропуски.

## Backpressure

> **Backpressure** — управление ситуацией, когда producer создаёт сообщения быстрее, чем consumer или WebSocket-клиент успевает их обрабатывать.

## Rate limiting

> **Rate limiting** — ограничение числа команд за период по нескольким измерениям, например user/session/IP, чтобы защищать ресурсы и бизнес-операции.

## Observability

> **Observability** — способность понять внутреннее состояние системы по metrics, logs и traces, не добавляя специальный debug-код для каждого инцидента.

## SLI и SLO

> **SLI** — измеряемый показатель качества, например доля успешных `PlaceBet`. **SLO** — целевое значение SLI за период.

## Главная схема

```text
Client WebSocket
→ Gateway: auth, rate limit, envelope, connection
→ Casino gRPC: правила комнаты и ставки
→ Wallet gRPC: финансовый invariant
→ Gateway: response/broadcast
```

```text
Reconnect(last_revision)
→ revision непрерывна → replay допустимых событий
→ есть gap/история недоступна → свежий snapshot
```

# 2. Подробные объяснения — понять

## 2.1. Что делает и не делает Gateway

Gateway делает:

- TLS/HTTP/WebSocket edge;
- authentication токена или session;
- rate limiting и message size limits;
- валидацию transport envelope;
- routing в Identity/Wallet/Casino;
- mapping gRPC errors в клиентский protocol;
- connection registry и broadcast;
- correlation ID и transport metrics.

Gateway не делает:

- расчёт payout;
- проверку доступного balance;
- изменение Round/Bet/Ledger;
- хранение полной User/Wallet/Casino models;
- принятие финансовых или игровых бизнес-решений.

## 2.2. Versioned WebSocket envelope

Команда клиента:

```json
{
  "version": 1,
  "type": "command.place_bet",
  "request_id": "2ad1...",
  "correlation_id": "f09b...",
  "room_id": "room-uuid",
  "payload": {
    "amount_minor": 1000
  }
}
```

Ответ:

```json
{
  "version": 1,
  "type": "response.place_bet",
  "request_id": "2ad1...",
  "ok": true,
  "revision": 42,
  "payload": {
    "bet_id": "bet-uuid",
    "status": "accepted"
  }
}
```

Ошибка тоже является частью контракта:

```json
{
  "version": 1,
  "type": "error",
  "request_id": "2ad1...",
  "ok": false,
  "error": {
    "code": "INSUFFICIENT_FUNDS",
    "retryable": false
  }
}
```

Не следует отправлять клиенту stack trace, SQL-текст или внутренний gRPC exception.

## 2.3. Минимальный FastAPI WebSocket lifecycle

```python
import asyncio
from fastapi import WebSocket, WebSocketDisconnect


async def websocket_endpoint(websocket: WebSocket, gateway):
    await websocket.accept()

    try:
        auth_message = await asyncio.wait_for(
            websocket.receive_json(),
            timeout=5.0,
        )
        principal = await gateway.authenticate(auth_message)
        connection = await gateway.register(principal, websocket)

        while True:
            message = await websocket.receive_json()
            response = await gateway.handle(connection, message)
            await websocket.send_json(response)
    except TimeoutError:
        await websocket.close(code=4401, reason="authentication timeout")
    except WebSocketDisconnect:
        pass
    finally:
        await gateway.unregister(websocket)
```

Production-реализация дополнительно ограничивает размер сообщения, частоту команд, число соединений, heartbeat, outbound queue и время внутренних RPC. Токен не следует без необходимости помещать в query string: URL может попасть в логи.

## 2.4. Reconnect и snapshot

Клиент хранит последнюю применённую revision:

```text
client revision = 39
server revision = 42
```

Варианты:

```text
есть события 40, 41, 42 → replay
нет полной истории → snapshot revision 42
```

Клиент сначала заменяет локальное состояние snapshot, затем применяет события только с revision `> 42`. Старое соединение той же session можно закрыть или пометить superseded, чтобы два соединения не отправляли конфликтующие команды.

Redis может хранить connection ownership и presence с TTL, но Room/Bet/Round остаются в Casino PostgreSQL. Потеря Redis не должна уничтожать бизнес-состояние.

## 2.5. Backpressure

Плохая схема — бесконечная очередь на каждого медленного клиента. Она приводит к росту памяти и устаревшим сообщениям.

```python
queue = asyncio.Queue(maxsize=100)


def enqueue_realtime(queue, event):
    try:
        queue.put_nowait(event)
    except asyncio.QueueFull:
        raise SlowConsumerError
```

Для состояния комнаты допустимо удалить промежуточные неприоритетные updates и отправить новый snapshot. Для подтверждения финансовой команды silent drop недопустим: нужен явный response/error.

## 2.6. Rate limiting

Один лимит по IP недостаточен:

```text
IP limit      → защищает edge от одного источника
user limit    → не даёт аккаунту обходить лимит через разные IP
room/action   → защищает дорогую операцию
connection    → ограничивает число одновременных WebSocket
```

Rate limit в Gateway защищает транспорт, но не заменяет idempotency и domain validation в Casino/Wallet.

## 2.7. Metrics без cardinality explosion

Хорошие метрики:

```text
websocket_connections{service="gateway"}
websocket_disconnects_total{reason="timeout"}
grpc_client_requests_total{target="wallet",method="ReserveFunds",code="OK"}
grpc_client_duration_seconds{target="wallet",method="ReserveFunds"}
place_bet_total{game="crash",result="accepted"}
outbox_unpublished_messages{service="wallet"}
```

Опасные labels:

```text
user_id, bet_id, room_id, request_id, correlation_id
```

Они имеют почти неограниченное число значений. Эти поля остаются в structured logs и traces.

## 2.8. Structured log

```json
{
  "timestamp": "2026-08-07T12:00:00Z",
  "level": "INFO",
  "service": "gateway",
  "event": "place_bet.completed",
  "correlation_id": "f09b...",
  "request_id": "2ad1...",
  "target": "casino",
  "duration_ms": 87,
  "result": "accepted"
}
```

Не логируются access/refresh tokens, passwords, raw cookies, Kafka credentials и полный sensitive payload.

## 2.9. Минимальные SLI для первой вертикали

| SLI | Что показывает |
|---|---|
| успешные auth handshakes | доступность входа в realtime |
| p95 command latency | задержку клиентской команды |
| доля gRPC errors по dependency | проблемы Identity/Casino/Wallet |
| active connections и disconnect reasons | здоровье WebSocket lifecycle |
| successful reconnect/snapshot | восстановление клиента |
| Wallet reserve/settle failures | финансовую надёжность |
| outbox lag/unpublished count | задержку надёжных событий |

# 3. Типовые ошибки

### Ошибка: Gateway становится владельцем всех DTO и правил

Gateway может адаптировать transport, но domain contract и решение остаются в сервисе-владельце.

### Ошибка: presence считается участием в комнате

Presence исчезает после TTL или потери Redis. Постоянное участие и ставка должны оставаться в Casino.

### Ошибка: reconnect просто открывает новый socket

Без revision и snapshot клиент может пропустить settlement или применить старые события.

### Ошибка: неограниченная очередь сообщений

Один slow consumer способен исчерпать память Gateway.

### Ошибка: один `requests_total` без причины и latency

Нужны rate, errors, latency и saturation; одна сумма запросов не объясняет деградацию.

### Ошибка: IDs в Prometheus labels

Это создаёт высокую cardinality и перегружает хранилище метрик.

# 4. Связный ответ для собеседования

> Gateway в realtime-системе завершает WebSocket, выполняет authentication edge, rate limiting, versioned envelope validation, routing и mapping ошибок, но не владеет бизнес-логикой. Состояние комнаты и revision принадлежат Casino; Redis хранит только connection ownership, presence и cache. При reconnect клиент передаёт последнюю revision: Gateway/Casino либо воспроизводит доступный gap, либо возвращает свежий snapshot. Для slow clients используются bounded queues и явная политика backpressure. Метрики содержат ограниченные labels, а request, user и correlation IDs находятся в structured logs и traces.
