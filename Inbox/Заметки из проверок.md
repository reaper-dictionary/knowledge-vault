
 PID - уникальный идентификатор процесса
 PPID - идентификатор родительского процесса

- `$!` — PID последнего процесса, запущенного в фоне;
- `ps -p "$!"` — показать именно этот процесс;
- `pid` — его идентификатор;
- `ppid` — идентификатор родителя;
- `stat` — состояние;
- `cmd` — запущенная команда.

`echo` — «выведи текст или значение»
`ps` — «покажи процессы»


Команда:

```
pgrep -a -x sleep
```

ищет процессы в системе:

- `pgrep` — поиск процесса;
- `-x` — имя должно точно совпадать с `sleep`;
- `-a` — показать PID и полную команду;


Команда `jobs -l` показывает фоновые задачи только текущего Bash:

- `[1]` — номер задачи внутри этой оболочки;
- `+` — текущая задача, которую Bash выберет по умолчанию;
- `15073` — её настоящий PID;
- `Running` — выполняется;
- `&` — была запущена в фоне.

| Состояние | Значение                                                                     | Наш пример             |
| --------- | ---------------------------------------------------------------------------- | ---------------------- |
| `R`       | Выполняется или готов выполняться                                            | `yes`                  |
| `S`       | Ожидает событие или таймер                                                   | `sleep`                |
| `T`       | Принудительно приостановлен                                                  | `sleep` после `Ctrl+Z` |
| `Z`       | Zombie: процесс уже завершился, но родитель ещё не забрал его код завершения |                        |
| `D`       | Неотменяемое ожидание внутри ядра, чаще всего операции ввода-вывода          |                        |
`\_` визуально обозначает дочерний процесс.
`$$` — PID текущего Bash;
`pstree -p "$$"`  - дерево дочеринх процессов от bash



`systemd` — главный системный менеджер большинства современных Linux-дистрибутивов. Обычно он запускается первым пользовательским процессом с `PID 1`, а затем:

- запускает системные службы;
- следит за ними;
- останавливает и перезапускает их;
- управляет автозапуском;
- связывает службы с системными журналами.

Основные понятия:

- `daemon` — программа, которая долго работает в фоне;
- `service` — описание того, как управлять такой программой;
- `unit` — общий объект `systemd`; служба является юнитом типа `.service`;
- `systemctl` — команда управления `systemd`;
- `journalctl` — команда чтения системных журналов.


- `PID 1` — `systemd` был первым процессом, запущенным ядром.
- `PPID 0` — его создало непосредственно ядро; обычного родительского процесса у него нет.
- `S` — сейчас ожидает события, а не постоянно занимает CPU.
- `s` — лидер сессии.
- Все остальные системные процессы прямо или косвенно происходят от PID 1.



Docker socket (`/var/run/docker.sock`) — это главный файл, через который Docker CLI и другие программы общаются с фоновой службой управления контейнерами (Docker Daemon). 

Как это работает
- Принимает команды от клиента в виде HTTP-запросов через локальный файл вместо сетевого порта.
- Позволяет запускать, останавливать и удалять контейнеры.
- Передает данные быстро и без использования сети.
