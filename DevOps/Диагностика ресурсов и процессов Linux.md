
### Общая нагрузка

```
nproc
uptime
```

- `nproc` — количество логических ядер.
- `load average` — среднее количество активных и ожидающих задач за 1, 5 и 15 минут.
- Нагрузку нужно сравнивать с количеством ядер и смотреть, сохраняется ли она длительное время.

### Оперативная память

```
free -h
```

Главные значения:

- `used` — используемая память;
- `free` — полностью пустая память;
- `buff/cache` — кэш Linux;
- `available` — сколько памяти можно отдать новым программам;
- `swap` — резервная память на диске.

Кэш физически занимает RAM, но Linux может освободить его при необходимости. Поэтому важнее смотреть на `available`, а не только на `free`.

Подробные замеры:

```
vmstat 1 5
```

Основные столбцы:

- `r` — задачи, ожидающие CPU;
- `b` — задачи, заблокированные ожиданием;
- `si/so` — чтение и запись swap;
- `id` — простой CPU;
- `wa` — ожидание диска.

### Диск

```
df -h /
```

Показывает заполнение файловой системы.

```
du -sh <путь>
du -sh *
```

Показывает размер конкретного каталога или содержимого текущего каталога.

```
df — какой раздел заполнен
du — какие файлы и каталоги заняли место
```

### Поиск тяжёлых процессов

По CPU:

```
ps aux --sort=-%cpu | head -5
```

По RAM:

```
ps aux --sort=-%mem | head -5
```

Интерактивный просмотр:

```
btop
```

В `ps`:

- `PID` — идентификатор процесса;
- `%CPU` — потребление CPU;
- `%MEM` — доля RAM;
- `RSS` — реальная память процесса;
- `VSZ` — виртуальное адресное пространство;
- `STAT` — состояние процесса.

### Остановка процессов

Обычный процесс:

```
kill <PID>
```

Процесс под управлением systemd:

```
systemctl stop <service>
systemctl --user stop <service>
```

Для systemd-сервиса предпочтительнее `systemctl stop`: он корректно остановит весь юнит и его дочерние процессы.

### Порядок диагностики

Если не работает один сервис:

```
systemctl status → journalctl -u
```

Если тормозит вся система:

```
uptime → free -h → df -h → ps или btop
```

Полная последовательность:

```
systemctl status <service>
journalctl -u <service> -n 20
uptime
free -h
df -h /
ps aux --sort=-%cpu | head -5
```

Если знаешь только PID, systemd умеет сам найти связанный юнит:

```
systemctl status <PID>
```

Для пользовательского процесса:

```
systemctl --user status <PID>
```

Например:

```
systemctl --user status 70482
```
